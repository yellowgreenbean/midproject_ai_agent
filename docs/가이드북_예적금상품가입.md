# 1부 — 구현한 기능

## 0. 한눈에 보기

### 0-1. 목적
- **실제 은행처럼 상품을 골라 가입한다.** 과제 필수 조건 「계좌 생성은 상품별 금리·가입 조건 등 실제 은행 기능과 UI 를 참고」 — 두린은행(원본 우리은행) 정기예금 11개 + 적금 19개 중 하나를 골라, 금액·기간에 맞는 금리로 예상 이자를 보고, 내 입출금 계좌에서 돈을 빼 가입한다.
- **가입한 뒤에도 돈이 제대로 움직인다.** 적금은 다음 회차부터 직접 더 넣고(PROD-F12), 만기일이 되면 원금 + 이자가 출금 계좌로 돌아온다(PROD-F11). 끝낼 방법이 있어야 계좌 해지·회원 탈퇴도 풀린다(기획서 Part 3 변경 이력(3)).
- **본인 것만, 한 번만.** 남의 계좌·계약에는 닿지 못하고(404), 중요한 작업마다 본인 확인(step-up)을 다시 받고, 같은 가입 요청이 두 번 와도 계약은 하나만 생긴다.
- 이번 대화에서 채운 빈 곳 세 가지:
  1. 상품 데이터에 **적금 납입 방식**(정액적립식 / 자유적립식)이 없었다 → `payment_types` 추가
  2. 화면은 「돈 넣기」를 부르는데 서버에 **추가 납입 API 가 없었다** → `POST /subscriptions/{id}/payments`
  3. **만기 처리 배치가 없었다** → `app/jobs.py` `mature_subscriptions`

## 1. 적금 납입 방식 — 데이터와 규칙

### 1-1. 상품 데이터 (`data/dummy/products/products.json`)
적금 19개의 `product_rules[].rules_json` 에 `payment_types` 를 넣었다. 예금 11개에는 넣지 않는다.

| 값 | 상품 | 근거 (상품설명서 `data/rag/products/<상품>.md`) |
|---|---|---|
| `["FIXED"]` 정액만 | prod_015 · prod_019 | prod_019 「상품유형 • 정기적금 (정액적립식)」, prod_015 상품 소개 「정액적립식 적금」 |
| `["FIXED", "FREE"]` 둘 다 | prod_004 · prod_032 | 「상품유형 • 정액적립식 / 자유적립식」 |
| `["FREE"]` 자유만 | 나머지 15개 | 「상품유형 • 자유적립식」 |

`meta.payment_types` 에도 같은 설명을 적었고, 출처 표는 `docs/domain-rules.md` 5-1 끝에 있다.

### 1-2. 계약 하나의 납입 방식은 `monthly_amount` 로 안다
| 계약 | `monthly_amount` | 납입 방식 |
|---|---|---|
| 정액적립식 적금 | 가입 때 정한 월 납입액 (예: `50000`) | `FIXED` |
| 자유적립식 적금 | `null` | `FREE` |
| 예금 | `null` | 없음(`null`) |

`backend/app/savings.py` 의 `payment_type_of(product_type, monthly_amount)` 한 함수가 이 규칙을 정하고, 응답의 `payment_type` 도 여기서 나온다.

### 1-3. 회차
```
가입일 2026-11-10 · 12개월
 1회차 [11-10, 12-10)  ← 가입할 때 냄
 2회차 [12-10, 01-10)
 …
12회차 [10-10, 11-10)   만기일 2027-11-10 부터는 못 냄 (PAYMENT_PERIOD_ENDED)
```
- 정액: 회차 안에 한 번이라도 냈으면 `ALREADY_PAID_THIS_PERIOD`. 금액은 `monthly_amount` 와 같아야 한다.
- 자유: 한 번에 상품 최소 금액(`monthly_min`, 없으면 1원) 이상·단위(`monthly_unit`)에 맞게, 회차 합계 ≤ 상품 월 한도(`monthly_max`).
- 말일 규칙은 만기일과 같다: 1월 31일 가입이면 2회차는 2월 28일(또는 29일)부터.

## 2. 만기 지급 계산 (PROD-F11, [모의 규칙])
- 원금 = `subscriptions.principal`(적금은 납입 누계).
- 이자 = 단리·세전·원 미만 버림·가입 때 금리 `applied_rate`.
  - 예금: 원금 × 연이율 × 꽉 찬 개월 / 12 (일 단위 상품은 × 일수 / 365)
  - 적금: 납입 기록마다 「납입액 × 연이율 × 그 납입일부터 만기일까지 꽉 찬 개월 / 12」를 더한다 → **놓친 회차만큼 이자가 줄어든다**
- 예: 정액 1만 원 × 12회 · 연 2.40% → 10,000 × 0.024 × (12 + 11 + … + 1) / 12 = **1,560원**, 지급액 121,560원 (`test_maturity_pays_principal_and_interest`).
- 출금 계좌가 정지면 지급하지 않고 알림만 한 번(`<계약 id>:HOLD`). 정지가 풀리면 다음 실행에서 지급한다(기획서 Part 3 4장).

## 3. 겪은 문제와 해결 (같은 일을 다시 할 때 참고)

### ① `AssertionError: cd backend && .venv\Scripts\python -m app.jobs …` (문자열 바꾸기 스크립트가 원문을 못 찾음)
- 원인: `jobs.py` 맨 위 설명문에는 `\\Scripts\\` 처럼 역슬래시가 두 번 적혀 있는데, 바꾸기 스크립트 안에서 역슬래시를 다시 이스케이프하며 개수가 달라졌다.
- 해결: 역슬래시가 없는 짧은 조각(`# 아래 다섯 가지를 한 번씩`)만 찾아 바꾸었다. **고칠 곳을 찾을 때는 특수 문자가 없는 조각을 고른다.**

### ② 명령이 2분 동안 끝나지 않음
- 원인: 명령 앞에 실수로 `cat > /tmp/x.txt` 를 붙여, `cat` 이 키보드 입력을 끝없이 기다렸다.
- 해결: 그 작업을 멈추고, 스크립트를 파일로 저장한 뒤 `python 스크립트.py` 로 다시 실행했다.

### ③ `AssertionError: 흐름도에 중도 해지·만기 갈래 추가.` (기획서 고치기)
- 원인: 기획서의 변경 이력 줄은 **줄 끝에 공백 두 칸**(마크다운 줄바꿈)이 있는데, 스크립트 파일을 저장하며 끝 공백이 사라졌다.
- 해결: 공백을 `chr(32) * 2` 로 코드에서 만들어 붙였다. 줄 끝 공백은 `sed -n <줄>p 파일 | cat -A` 로 `.  $` 처럼 보인다.

### ④ 기존 시험 4개가 `PAYMENT_TYPE_REQUIRED` 로 실패
- 원인: 기존 시험이 쓰던 prod_004 는 정액·자유 **둘 다** 되는 상품이라, 이제 납입 방식을 꼭 보내야 한다.
- 해결: 서버 검사 순서를 바꾸지 않고(납입 방식도 금액·기간처럼 입력값이라 그 바로 뒤에 검사) 시험 도우미 `validate` · `subscribe` 가 prod_004 에 `payment_type: "FIXED"` 를 보내게 했다.

### ⑤ 개발 서버 8010 이 예전 코드를 돌리고 있음
- 증상: `GET /products/prod_004` 응답에 `payment_types` 가 없다.
- 원인: `--reload` 로 켠 서버가 새 코드를 읽지 않았다(이 PC 에서는 `--reload` 가 믿을 만하지 않다).
- 해결: 켜져 있던 서버는 건드리지 않고 **8011 에 새로 켜서** 예시를 받았다. 화면으로 쓰려면 8010 서버를 끄고 `--reload` 없이 다시 켜야 한다(4-2).

### ⑥ 예시 스크립트의 DB 읽기가 시험 DB 를 읽음
- 원인: 예시 스크립트가 `tests.conftest` 를 import 하자 DB 주소가 시험 DB(`midproject_test`)로 바뀌었다(conftest 가 그렇게 설정한다).
- 해결: HTTP 요청은 8011(개발 DB)로 갔으므로 응답은 맞다. 잔액은 conftest 없이 따로 읽었다(개발 DB `acc_022`: 2,992,700원 → 2,792,700원, 가입·납입 3건 합 200,000원과 같음).

### 4-2. 서버 켜고 API 눌러 보기 (Swagger `http://localhost:8010/docs`)

1. `POST /auth/login` — 더미 회원(예: `user_016`, 비밀번호는 `backend/.env` 의 `SEED_PASSWORD`)

### P5. `POST /products/{productId}/validate` — 가입 직전 검사
**바뀐 점**: 요청에 `payment_type`(선택), 오류 `PAYMENT_TYPE_REQUIRED` · `PAYMENT_TYPE_NOT_ALLOWED`.

| 이름 | 위치 | 타입 | 필수 | 제약 · 설명 |
|---|---|---|---|---|
| `payment_type` | 본문 | `"FIXED"` \| `"FREE"` | 아니오 | 적금만 본다. 상품이 한 가지 방식만 받으면 비워도 그것으로, 둘 다 받으면 **필수**. 예금은 무시 |

오류 — 검사 순서: 회원 상태 → 상품·금액·기간·금리(P4 와 같음) → **납입 방식** → 계좌 → 잔액 → 1인당 개수

| HTTP | code | message | 언제 |
|---|---|---|---|
| 422 | `PAYMENT_TYPE_REQUIRED` | 정액적립식과 자유적립식 중 납입 방식을 골라 주세요. | 둘 다 받는 상품(prod_004·prod_032)인데 비움 |
| 422 | `PAYMENT_TYPE_NOT_ALLOWED` | 이 상품은 정액적립식만 가입할 수 있어요. | 상품이 받지 않는 방식(예: prod_015 에 `FREE`) |
| 422 | `VALIDATION_ERROR` | 요청 값을 확인해 주세요. | `FIXED`·`FREE` 말고 다른 글자 |

| 401 | `UNAUTHORIZED` · `SESSION_EXPIRED` | (공통) | 로그인 안 함·세션 끊김 |
| 422 | `VALIDATION_ERROR` | 요청 값을 확인해 주세요. | `amount`·`step_up_challenge_id` 빠짐·너무 김 |
| 404 | `SUBSCRIPTION_NOT_FOUND` | 가입 상품을 찾을 수 없어요. | 없는 계약 **또는 남의 계약** |
| 403 | `STEP_UP_REQUIRED` | 본인 확인을 다시 해 주세요. | 번호가 없음 · 이 회원·이 세션·`SUBSCRIPTION` 작업의 번호가 아님 · 이미 씀 · 5분 지남 (`consume_step_up`) |
| 403 | `USER_NOT_ACTIVE` | 지금 계정 상태에서는 가입할 수 없어요. | 회원이 `ACTIVE` 가 아님(`RESTRICTED` 등) |
| 409 | `SUBSCRIPTION_NOT_ACTIVE` | 이미 끝난 가입 상품이에요. | `MATURED`·`TERMINATED` |
| 422 | `NOT_INSTALLMENT_SAVINGS` | 예금에는 돈을 더 넣을 수 없어요. 적금만 추가로 넣을 수 있어요. | 예금 계약 |
| 409 | `PAYMENT_PERIOD_ENDED` | 만기일이 되어 더 넣을 수 없어요. | 오늘 ≥ 만기일 |
| 422 | `AMOUNT_OUT_OF_RANGE` | 넣을 돈을 숫자로 입력해 주세요. | 숫자가 아니거나 0 이하 |
| 409 | `ALREADY_PAID_THIS_PERIOD` | 이번 회차는 이미 넣었어요. 다음 회차는 12월 10일부터 넣을 수 있어요. | 정액, 이번 회차에 이미 냄 |
| 422 | `AMOUNT_OUT_OF_RANGE` | 정액적립식은 가입 때 정한 50,000원만 넣을 수 있어요. | 정액, 금액이 월 납입액과 다름 |
| 422 | `AMOUNT_OUT_OF_RANGE` | 한 번에 1원 이상 넣어 주세요. (단위가 있으면 「, 1,000원 단위로」) | 자유, 최소 금액 미만·단위 안 맞음 |
| 422 | `MONTHLY_LIMIT_EXCEEDED` | 이번 회차에는 350,000원까지 더 넣을 수 있어요. (회차 한도 500,000원, 12월 10일부터 새 회차) | 자유, 회차 합계가 상품 월 한도를 넘음 |
| 422 | `ACCOUNT_NOT_ACTIVE` | 출금 계좌가 정상이 아니에요. 계좌 정지를 먼저 풀어 주세요. | 출금 계좌가 정지·해지 |
| 422 | `INSUFFICIENT_BALANCE` | 잔액이 부족해요. (지금 잔액 N원) | 잔액 < 넣을 돈 |

실패하면 아무것도 남지 않는다(잔액·납입 기록·원금 그대로, 본인 확인 번호도 다시 쓸 수 있음).

### S4. `POST /subscriptions/{subscriptionId}/terminate` — 중도 해지
바뀌지 않았다. 응답이 S2 모양이라 `payment_type`·`next_period_start` 가 함께 온다. 규칙은 기획서 Part 3 PROD-F10.

### (예약 작업) `mature_subscriptions` — 만기 지급
HTTP API 가 아니다. 서버 안 스케줄러가 1분마다(`app.jobs.run_minutely`), 또는 손으로 `cd backend && .venv\Scripts\python -m app.jobs`.

| 경우 | DB 에 남는 것 | 알림 (`notifications`) |
|---|---|---|
| 출금 계좌 `ACTIVE` | `transactions` 에 `SUBSCRIPTION_PAYOUT`(원금+이자), 계약 `MATURED` · `closed_at` 오늘 | `MATURITY` 「○○ 만기 금액을 보냈어요」, `event_id` = 계약 id |
| 출금 계좌 정지 | 바뀌지 않음(계약 `ACTIVE`) | `MATURITY` 「○○ 만기 금액을 아직 못 보냈어요」 한 번만, `event_id` = `<계약 id>:HOLD` |
