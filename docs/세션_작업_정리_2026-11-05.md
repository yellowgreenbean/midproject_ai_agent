## 요구사항별로 추가·수정한 사항

### 1. sql 폴더를 Docker로 올리는 방법

- 파일 변경은 없습니다. 방법을 설명하고, MySQL 8.0 컨테이너로 시험했습니다.
- 확인한 것
  - `docs/sql`을 `/docker-entrypoint-initdb.d`에 붙이면 표 60개와 보기 1개가 생깁니다.
  - 한글 주석이 깨지지 않습니다.
  - `seed.sql`로 회원 300명이 들어갑니다.
- 알려 드린 주의점
  - 컨테이너는 파일마다 따로 접속하므로, `MYSQL_DATABASE`를 정하지 않으면 01번 파일부터 실패합니다.
  - initdb는 볼륨이 비어 있을 때 한 번만 실행됩니다.

### 2. MySQL로 진행한 이유

- 파일 변경은 없습니다.
- 제가 MySQL을 고른 게 아니라, 처음 올라온 스키마(커밋 `472d020`)부터 MySQL 8.0 문법이었습니다. 저장소에도 이유가 적혀 있지 않았습니다.
- PostgreSQL로 옮기면 고쳐야 하는 문법(ENUM, COMMENT, KEY, ON UPDATE, DATE_FORMAT 등)을 정리해 드렸습니다.

### 3. MySQL → PostgreSQL 17 전환 — 커밋 `83b635a`

| 파일 | 수정 |
|---|---|
| `docs/sql/00_common.sql` | `CREATE DATABASE`·`USE`를 지움<br>DB 기본 시간대를 `Asia/Seoul`로 고정<br>`set_updated_at()` 트리거 함수를 추가<br>실행 방법을 PostgreSQL에 맞게 다시 씀 |
| `docs/sql/01~07` | `ENUM` → `VARCHAR(30)` + `CHECK`<br>`DATETIME` → `TIMESTAMP(0)`, `TINYINT` → `SMALLINT`, `JSON` → `JSONB`<br>`COMMENT` → `COMMENT ON`<br>`KEY` → `CREATE INDEX`<br>`ON UPDATE CURRENT_TIMESTAMP` → 표 5개에 트리거<br>`DATE_FORMAT` → `to_char`<br>`FOREIGN_KEY_CHECKS`를 지움<br>파일마다 `SET client_encoding = 'UTF8'` |
| `scripts/generate_seed.py` | PostgreSQL용으로 출력(한 트랜잭션, `TRUNCATE` 한 문장, `\` 이스케이프 제거) |
| `docs/seed.sql` | 다시 생성. INSERT 데이터는 이전과 같음 |
| `docs/기획서.md` | MySQL 예시 SQL 3곳을 PostgreSQL 문법으로 바꿈(`ON CONFLICT`, `CURRENT_DATE + 3`, `INTERVAL '6 months'`), 변경 이력 (17) 추가 |

- 검증(postgres:17): 표 60, 보기 1, FK 91, 트리거 5, 칸 주석 141개(원본과 같음). 60개 표의 건수가 모두 일치했습니다.
- 알려 드린 동작 차이
  - 따옴표 없는 이름은 소문자로 바뀝니다. 이 문제는 9번에서 따옴표로 해결했습니다.
  - 글자 비교가 대소문자를 구분합니다.
  - ENUM의 정렬 순서가 사라집니다.
  - FK 검사를 끌 수 없습니다.
  - FK 칸에 인덱스가 자동으로 생기지 않습니다.

## seed가 필요한 상황 (규칙 ③ — 실행 전 허락 받음)

더미 데이터(`data/dummy`)로 채울 수 있는 표는 `users` 30, `accounts` 24 + `account_balances`, `transactions` 89, `user_cards` 30, `card_transactions` 132, `card_bills` 30, `products` 30(+ 금리 109, 조건 30), `subscriptions` 10, `subscription_payments` 1입니다.

seed가 필요한 경우는 다음 세 가지뿐입니다.

1. **FK 때문에 꼭 있어야 하는데 더미에 없는 부모 데이터**: `card_companies`·`card_products`(카드 이름 5개), `categories`·`merchants`(가맹점 34곳), `billing_cycle_rules`. 이게 없으면 카드·승인 내역을 넣을 수 없습니다.
   - seed 대신 더미의 이름에서 뽑아 만드는 방법도 있습니다.
2. **더미가 없는 기능을 시험할 때**: 이체, 예약 송금, 자주 쓰는 계좌, 이체 한도, 타행 계좌(`external_accounts`), 카드 포인트, 알림
3. **로그인 시험**: 비밀번호·PIN 해시(`local_credentials`, `pin_credentials`). 규칙상 더미에 비밀번호를 넣지 않습니다.
